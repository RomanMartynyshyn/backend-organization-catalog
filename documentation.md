# Документація: Двоетапна архітектура імпорту Організацій

Цей документ описує логіку роботи створеного рішення для безпечного імпорту великих відкритих XML-файлів (4.5 ГБ) та збагачення даних за допомогою закритого Tax API. Рішення спроєктовано для роботи в умовах суворих обмежень по оперативній пам'яті (3.5 ГБ) та жорстких лімітів API (1 запит на 90 секунд).

## 1. Проблема та Архітектурне Рішення

**Проблеми:** 
1. Файли розміром 4.5 ГБ неможливо завантажити в оперативну пам'ять (впаде з "Out of Memory").
2. Потрібно виділити компанії виключно з міста Кривий Ріг.
3. Податкове API (яке має адреси) дозволяє робити лише 1 запит на 90 секунд (1000 на день), що робить неможливим швидку перевірку мільйонів компаній.

**Рішення (Двоетапний пайплайн):** 
1. **Етап 1: Грубий та швидкий парсинг (XML).** Стрімінговий парсер `sax` читає файл "на льоту" (споживає ~50 МБ пам'яті). Він збирає базові дані та фільтрує компанії, у назві яких зустрічається "Крив". Ці організації швидко зберігаються в базу без адрес.
2. **Етап 2: Повільне збагачення (Tax API).** Фоновий скрипт знаходить у базі компанії без адрес і повільно (1 запит у 90 секунд) відправляє їхні ЄДРПОУ до податкової, отримуючи точні адреси та статуси.

## 2. Зміни в Базі Даних (Prisma Schema)

Для збереження розширених даних з XML було оновлено файл `prisma/schema.prisma`. В таблицю `Organization` додано поля:
- `edrpou` (Унікальний код) — для ідентифікації та оновлення.
- `address` — Повна адреса організації (витягується з API).
- `legalStatus` — Поточний статус (наприклад, "зареєстровано").
- `founders` — Засновники (зберігаємо як довгий текст).
- `director` — Директор або керівник (`<SIGNER>`).
- `organizationType` — Організаційно-правова форма (`<OPF>`).
- `registrationDate` — Дата реєстрації (`<REGISTRATION>`).
- `shortName` — Коротка назва (`<SHORT_NAME>`).

## 3. Логіка роботи Скриптів

### 3.1. Грубий Парсер (`src/utils/importXml.js`)
1. **Читання:** Скрипт відкриває файл через `fs.createReadStream()` і читає його як потік.
2. **Збір даних:** Парсер ловить відкриття тегів та збирає накопичений текст у змінну `activeText` (щоб уникнути втрати тексту, який `sax` може розбити на шматки).
3. **Фільтрація:** Перевіряється `isKryvyiRih(currentOrg.name)`.
4. **Батчинг та Черга (Queue):** Щоб база даних не відхиляла запити (`pool timeout`), скрипт збирає 500 організацій, пакує їх у Чергу (`batchQueue`) і зупиняє читання файлу (`fileStream.pause()`). Потім послідовно і безпечно виконує збереження, після чого поновлює читання.
5. **Прогрес:** Щоб скрипт не виглядав "завислим" під час довгого пошуку, він кожні 50 000 перевірених записів виводить звіт у термінал.

### 3.2. Фоновий Збагачувач (`src/jobs/enrichOrganizations.js`)
1. Скрипт шукає в базі першу організацію, у якої поле `address` досі пусте (`null`).
2. Робить POST запит через бібліотеку `axios` до `cabinet.tax.gov.ua`, передаючи ЄДРПОУ та Токен доступу.
3. Отримує точні дані (`ADRESS`, `FULL_NAME`, `C_STAN`) і оновлює запис у базі.
4. Чекає 90 секунд (`setTimeout(90000)`) і переходить до наступної організації. Це гарантує, що API податкової не заблокує IP-адресу вашого сервера.

## 4. Як це все запускати

Для повного циклу імпорту вам потрібно запустити обидва скрипти (можна паралельно у двох терміналах).

### Етап 1: Парсинг відкритого реєстру (XML)
Покладіть завантажений XML файл у папку проекту і виконайте:
```bash
node src/utils/importXml.js назва_файлу.xml
```
*Скрипт виводитиме прогрес кожні 50к організацій. Чекайте повідомлення "Парсинг та імпорт завершено успішно!".*

### Етап 2: Запуск збагачувача адрес (Tax API)
**ВАЖЛИВО:** Перед запуском відкрийте файл `src/services/taxApi.js` (рядок 4) і замініть слово `'твой_токен'` на ваш реальний ключ доступу до Tax API, інакше податкова буде відхиляти запити (Помилка 400).
```bash
node src/jobs/enrichOrganizations.js
```
*Цей скрипт працює безкінечно у фоновому режимі.*
